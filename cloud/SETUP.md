# Подключение Firebase

1. В Firebase Console войти как dshtriters@gmail.com. Создать проект и веб-приложение KREDOS.
2. Authentication → Sign-in method: включить Google и Email/Password. Указать email поддержки владельца. Authentication → Settings → Authorized domains: добавить virus53111.github.io.
3. Создать Cloud Firestore в production mode. Выбрать подходящий регион до создания базы.
4. Скопировать публичный firebaseConfig веб-приложения в cloud-config.js: window.KREDOS_FIREBASE_CONFIG = { ... }; Значения являются публичной конфигурацией клиента, не серверным ключом. Не добавлять service-account ключи.
5. Опубликовать cloud/firestore.rules через вкладку Rules в Firebase Console, либо из репозитория:

```sh
npm ci
npx firebase-tools@14.12.0 login
npx firebase-tools@14.12.0 deploy --only firestore:rules --project YOUR_PROJECT_ID
npm run build:cloud
npm test
npm run test:rules
```

6. Опубликовать файлы на GitHub Pages. Войти владельцу через Google либо подтвердить email после регистрации. Проверить на второй учетной записи запрет редактирования и удаления, назначение и отзыв модератора.

| Роль | Просмотр | Добавление / изменение | Удаление | Назначение модераторов |
|---|---|---|---|---|
| Подтверждённый пользователь | Да | Нет | Нет | Нет |
| Модератор | Да | Да | Нет | Нет |
| dshtriters@gmail.com | Да | Да | Да | Да |

Сервер проверяет подтверждённый email владельца, назначение модератора и ревизию заказа. Роли не назначаются через localStorage. Общие заказы имеют отдельное представление для чтения; локальные черновики отделены по uid. Каталог остаётся доступным только для добавления и восстанавливает исходные материалы.

Установка PWA: Android — меню Chrome «Установить приложение»; iPhone — Safari «Поделиться» → «На экран Домой»; компьютер — кнопка установки в поддерживаемом браузере. Каталог и черновики доступны без сети. Вход и общие заказы требуют подключения. Интерфейс русский, латышский, украинский.
